End matterProjects and Competitions

A book you only read teaches less than a book you build from. These projects turn the theory into working systems: each names an artifact to construct, hands you a dataset, fixes a metric, and states a measured bar to beat. They run on a laptop with the same pure-numpy discipline as the worked examples, and each is also set up to become a Kaggle community competition, with a hidden test set and a live leaderboard, so a class or a reading group can compare solutions. The final project pulls the whole book together; the capstones each go deep on one arc. None of them is a contest to be won by a hundredth of a point. Success is building the method and watching the property the chapter promised appear, then clearing the provided baseline by a clear margin with a kernel you understand.

How the projects work

Every project is specified the same way, so you always know what "done" means. A Goal names the artifact and the observable you are after. A Data line says what you are given; the datasets are generated by reproducible scripts under projects/ in the book's repository, so nothing is a black box and you can regenerate or resize any of them. A Metric is the single number a submission is scored on. A Success line is the honest bar: a baseline we actually ran and measured, which your kernel method should beat, stated as a number wherever the dataset is already generated. And a short list of Milestones is the path, not a tutorial: a sequence of working intermediate results, each of which teaches something even if you stop there.

Two principles run through all of them. The first is local-first: every dataset is small enough to fit and solve on a laptop, because the point is to understand the method, not to marshal a cluster; the one project that outgrows an exact solve does so on purpose, to force the approximations of the large-scale chapter. The second is honesty over leaderboards, the same ethos as the rest of the book: the baselines are real, the target numbers were measured by a script you can read, and the win is a method whose behavior you can explain, not an ensemble you cannot. Each project closes by asking you to write down not just your score but which chapter's result made it work.

Running a project as a Kaggle competition

Each project maps onto a Kaggle community competition with no code changes. The generator writes three files: train.csv with labels, test.csv without, and solution.csv with the held-out labels and a public/private split. Upload the training and test files as the competition data, the solution file as the scoring key, pick the stated metric, and paste the brief from projects/<name>/competition.md as the description. Entrants then submit predictions on the test set and are ranked on the private split at the close. The book's version and the competition's version share the same data and the same metric, so a solution developed against the local files scores identically on the leaderboard.

The final project

The last thing to build is the whole thing at once. This project refuses to let any single technique carry it: the data is heterogeneous, so you must design a kernel; the payoff is a decision, so you must quantify uncertainty; and the setting is deployment, so you must attribute predictions and detect drift. It is the argument of the accountability chapter and the practice of the applications chapter, made concrete on one dataset, and it exercises the kernel-design ideas of Part VII, a supervised machine from Part II, and the calibrated uncertainty of Part XI along the way.

Final Project (Kernels, End to End)

Goal Build a complete, accountable kernel system for a sensor-monitoring problem whose records mix numeric features with a short categorical tag sequence, and whose deployment inputs have drifted from the calibration period. Deliver point predictions, certified 90% intervals, and a one-page model card.

Data A synthetic mixed-type dataset (numeric readings plus a per-record symbol sequence) with a planted covariate shift between a labeled calibration period and the unlabeled deployment test set, so the drift is real rather than assumed.

Metric The mean 90% interval (Winkler) score on the deployment set, which rewards accuracy and calibration together; ties broken by point-prediction error.

Success Certified coverage between 0.88 and 0.92 on the public split, an interval score below the provided end-to-end baseline, and a model card that reports the MMD drift p-value between calibration and deployment inputs and the training points most responsible for a sample prediction.

  1. Design the kernel: compose an RBF kernel on the standardized numeric features with a spectrum (string) kernel on the tag sequence, summing valid kernels by the Mercer closure of the kernel-families chapter.
  2. Fit and select: train kernel ridge regression or a Gaussian process, tuning the composition weight and bandwidths by the closed-form leave-one-out of the ridge chapter.
  3. Certify the interval: wrap the fit in split conformal for a distribution-free 90% band, and check its coverage on a held-out calibration slice.
  4. Audit the deployment: run the MMD two-sample test between the calibration inputs and the deployment inputs, report the statistic and p-value, and note what a rejection means for the conformal guarantee.
  5. Report: produce the model card, naming the top influential training points for one prediction (closed-form leave-one-out), the drift result, and the exact reproducible configuration, the artifacts the accountability chapter argues a kernel model supplies for free.

Capstone projects

The capstones each take one arc of the book to a self-contained buildable result. Three of them already ship with generated data and a measured baseline; the rest state the same structure and open as their datasets are stood up. Do them in any order, though the calibrated-regression one is the gentlest start and the best warm-up for the final project.

Calibrated Regression

An accurate point prediction with a dishonest error bar is worse than useless in the sciences of the science-and-space chapter, because a decision will be made on the interval. Here the noise varies strongly across the input space, so a single global error bar cannot be right everywhere: it is either too wide where the data are clean or too narrow where they are noisy. The winning move is a locally-adaptive interval, and the metric is built to reward exactly that.

Capstone (Calibrated Regression)

Goal A regressor that is accurate and reports honest, locally-adaptive 90% intervals.

Data Six-feature tabular regression with strongly input-dependent (heteroscedastic) noise; 6000 labeled rows, 4000 test rows. Ready now under projects/calibrated-regression/.

Metric Mean 90% interval (Winkler) score, lower is better.

Success Beat the provided global-conformal baseline (measured interval score 4.45 at coverage 0.91) while keeping coverage near 0.90; a normalized (locally-adaptive) conformal band reaches about 3.60.

  1. Fit a Gaussian process or kernel ridge model and read its native interval; measure where its coverage fails across the input space.
  2. Wrap it in global split conformal to restore marginal coverage; confirm you match the baseline score.
  3. Make the band adapt: normalize the conformal score by a predicted residual scale, so the width shrinks where the data are clean and grows where they are noisy.
  4. Report coverage overall and within input strata, and connect the gap between them to the marginal-versus-conditional discussion of the accountability chapter.

Sequence Family Detection

The objects here are not vectors: they are variable-length sequences over a twenty-letter alphabet, each belonging to a family defined by a short shared motif that has been mutated and hidden in a random background. Exact letter identity is a weak signal; shared sub-patterns are the real one, which is precisely what the string kernels of the sequence-kernel chapter and its efficient-evaluation companion capture, and the reason a kernel machine beats a bag-of-letters classifier so decisively.

Capstone (Sequence Family Detection)

Goal Classify sequences into their families using a string kernel and a support vector machine.

Data 1500 labeled and 1000 test sequences over eight families, length 60, with planted mutated motifs. Ready now under projects/sequence-family/.

Metric Macro (balanced) classification accuracy.

Success Clearly beat the provided single-letter-composition baseline (measured macro accuracy 0.39); a 3-mer spectrum kernel already reaches 0.91, and a mismatch kernel with a tuned SVM should push past it.

  1. Build the spectrum kernel: represent each sequence by its k-mer counts and take the inner product; cosine-normalize so length does not dominate.
  2. Relax to the mismatch kernel, letting near-matching k-mers contribute, and evaluate it without materializing the full feature space.
  3. Train one support vector machine, selecting k, the mismatch tolerance, and the penalty by nested cross-validation.
  4. Inspect the support vectors for a class and relate them to the planted motif, the example-based explanation of the accountability chapter.

Molecular Property Prediction

A molecule is a labeled graph, and a property that depends on the presence of a particular substructure is the cheminformatics problem in miniature. The Weisfeiler-Lehman subtree kernel of the graph-kernel chapter compares iteratively refined neighborhood patterns, so it can see the substructure that a crude size-or-degree summary misses.

Capstone (Molecular Property Prediction)

Goal Predict a binary property of small labeled graphs with a graph kernel and an SVM.

Data Synthetic molecule-like graphs whose property is determined by a planted subgraph motif; train labeled, test hidden. Dataset in preparation under projects/molecular-graphs/.

Metric Area under the ROC curve.

Success Clearly beat the provided degree-histogram baseline that ships with the data; a Weisfeiler-Lehman subtree kernel should separate the property-bearing graphs.

  1. Establish the baseline: a histogram of node degrees fed to a linear classifier, which is blind to the motif.
  2. Run Weisfeiler-Lehman relabeling for a few iterations, hashing each node's neighborhood into a refined label.
  3. Form the subtree kernel from the label-count vectors, normalize it, and train an SVM.
  4. Vary the number of iterations and connect the accuracy curve to the expressivity limits discussed in the graph-kernel chapter.

Distribution Shift Detection

Each item is a pair of samples, and the question is whether they came from the same distribution. A mean check catches a mean shift and misses a change of shape at the same mean; the maximum mean discrepancy of the mean-embedding chapter, with a characteristic kernel, catches all of them, which is the whole reason it is the right drift monitor in the accountability chapter.

Capstone (Distribution Shift Detection)

Goal Score each pair of samples for how strongly the two distributions differ.

Data 1200 labeled and 800 test pairs of 60 points in four dimensions; shifts are in mean, variance, or shape. Ready now under projects/distribution-shift/.

Metric Area under the ROC curve over the pairs.

Success Beat the provided mean-difference detector (measured AUC 0.65); an unbiased MMD statistic with an RBF kernel at the median-heuristic bandwidth reaches 0.93.

  1. Score pairs by the squared difference of sample means; note which shift types it misses.
  2. Replace it with the unbiased MMD U-statistic from the two samples' Gram blocks.
  3. Choose the kernel and bandwidth, and study how power depends on them.
  4. Calibrate a decision threshold by permutation, turning the score into a test with a controlled false-alarm rate.

Structure Without Labels

Kernels are not only for prediction. On data that lies on a nonlinear manifold, a linear method sees tangled clusters, while the kernel PCA of its chapter and the spectral clustering of the clustering chapter straighten the manifold in feature space and recover the structure.

Capstone (Structure Without Labels)

Goal Recover cluster structure on data where linear methods fail, using kernel methods.

Data Points on nonlinear manifolds (interleaving moons, concentric shells) with noise, plus a held-out set to cluster. Dataset in preparation under projects/unsupervised-structure/.

Metric Adjusted Rand Index against the hidden cluster labels.

Success Clearly beat input-space k-means on the held-out ARI; spectral clustering on an RBF affinity should recover the manifold.

  1. Run k-means in the input space and measure how the nonlinear structure defeats it.
  2. Build an RBF affinity and cluster its leading Laplacian eigenvectors (spectral clustering).
  3. As a bonus, project onto the top kernel-PCA components and denoise by reconstructing from them.
  4. Sweep the bandwidth and relate the result to the geometry of the geometric-kernel chapter.

The Big-Kernel Sprint

Everything else in the book assumed the Gram matrix fits in memory. This project deliberately breaks that assumption, so the approximations of the large-scale chapter stop being optional and become the method. The metric is accuracy under a budget: fast and nearly-exact beats exact and infeasible.

Capstone (The Big-Kernel Sprint)

Goal Fit a kernel model on a dataset too large for an exact solve, within a stated compute budget.

Data A large synthetic classification set where the full Gram matrix is infeasible. Dataset in preparation under projects/big-kernel-sprint/.

Metric Test accuracy achieved within a fixed wall-clock and memory budget (report both).

Success Come within a small accuracy gap of the exact solve estimated on a subsample, while staying inside the budget; report your approximation gap and speedup.

  1. Estimate the exact-solve accuracy and cost on a subsample, to know the ceiling and the wall.
  2. Fit with random Fourier features and measure the accuracy-versus-features curve.
  3. Fit with Nystrom, choosing landmarks by leverage scores, and compare at matched budget.
  4. Plot accuracy against wall-clock for both, and tie the number of landmarks you needed to the effective dimension of the practice chapter.

Design in N Queries

The last capstone is sequential. A hidden expensive function is out there, and you may evaluate it only a handful of times before you must commit to its optimum. This is the loop of the Bayesian optimization chapter and the on-the-fly experiments of the science-and-space chapter: the calibrated posterior, not the mean alone, decides where to spend the next query.

Capstone (Design in N Queries)

Goal Find the optimum of a hidden function in as few evaluations as possible, by letting the model's uncertainty choose each query.

Data A large pool of candidate inputs with hidden values; you may reveal a limited budget of labels before predicting the optimum. Dataset in preparation under projects/design-in-n-queries/.

Metric The best value found within the query budget (simple regret).

Success Beat random querying at the budget; a Gaussian process with expected improvement should reach the optimum in far fewer queries.

  1. Query at random and record the best-so-far curve, the baseline every method must beat.
  2. Fit a Gaussian-process surrogate to the revealed points and read its posterior over the pool.
  3. Query where the posterior variance is largest (uncertainty sampling), then where expected improvement is largest.
  4. Compare best-so-far curves and connect the saving to the on-the-fly active-learning mechanism of the science-and-space chapter.

What you will have built

Taken together, the capstones cover the working surface of the book: a calibrated regressor, a string-kernel classifier, a graph-kernel predictor, a distribution-drift monitor, an unsupervised manifold learner, a budget-bound large-scale solver, and a sequential experiment designer, each a small system you can run and explain. The final project assembles those instincts into one accountable pipeline of the kind the sciences actually deploy. The measure of success is not a leaderboard rank but a sentence you can write at the end of each: this is the kernel I chose, this is the property it gave me, and this is the result in the book that told me it would.
